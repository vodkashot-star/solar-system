# P0 Black-Screen Fixes — Implementation Plan

## Overview

Eliminate all known black-screen root causes on mobile (4–6 GB devices) by optimizing the Uranus GLB asset, deploying the Draco decoder pipeline, removing the synchronous 163 MB preload that blocks first paint, adding `invalidate()` calls that `frameloop="demand"` requires, recovering from WebGL context loss gracefully, and fixing camera framing to prevent planets from filling the viewport on narrow screens.

## Current State Analysis

The app suffers from multiple overlapping black-screen failure modes, all documented in `thoughts/tickets/ticket-001-black-screen.md` with a root-cause matrix of 9 symptoms. The dominant cause on 4 GB mobile devices is the 83 MB uncompressed `uranus.glb` (1.87M verts, 31 meshes) exhausting the GPU heap, followed by the 163 MB synchronous preload at `Planet.tsx:16-18` blocking first paint for 30–60 seconds on cellular connections. `frameloop="demand"` at `SolarSystem.tsx:46` means the canvas only re-renders when `invalidate()` is called — but several code paths never call it. No `webglcontextlost` event listener exists for recovery. Camera distance formulas at `CinematicTour.tsx:43` and `FocusCamera.tsx:20` use `visualRadius` only, ignoring Saturn's ring geometry (extends 8.66 units vs radius 1.9) and Uranus's actual bounding box, causing clipping on mobile viewports.

## Desired End State

After this plan is complete:
- App renders on iPhone SE (3 GB) and Galaxy A52 (4 GB) without black screen
- Loading spinner visible for < 10 seconds on 50 Mbps connection
- Fallback spheres appear immediately on page load; GLBs swap in asynchronously
- WebGL context loss shows recovery UI; context restore re-renders without page reload
- Saturn and Uranus tour segments frame the entire body (including rings) within viewport on 375 px wide screens
- Planets continue orbiting visually when tour is paused
- `npm run check` passes with no new TS errors

## Key Discoveries

- **Uranus GLB** is 83 MB / 1.87M verts / 31 meshes — generated by `scripts/generate_celestial_models.py:157-160` with `detail_level=3` subdivision. Median planet GLB is ~8 MB. Uranus is 400× more complex.
- **Draco decoder** at `draco-setup.ts:5-16` creates a `DRACOLoader` but never passes it to drei — `useGLTF` has its own internal loader. The `setDecoderPath('/draco/')` currently points to a dir with only a README (`public/draco/`).
- **Module-level preload** at `Planet.tsx:16-18` (`for...useGLTF.preload`) fires at module evaluation time, blocking all initialization until all 9 GLBs (163 MB) fetch and parse.
- **Planet `useFrame`** at `Planet.tsx:115-127` updates position/rotation every frame but never calls `state.invalidate()`, so planets appear frozen when tour is paused (OrbitControls triggers its own invalidate only on user interaction).
- **No context loss handler** exists in `SolarSystem.tsx:42-70` — `webglcontextlost` would silently kill the canvas.
- **Camera distance** formulas use `body.visualRadius * 4 + 3` (`CinematicTour.tsx:43`) and `body.visualRadius * 5 + 5` (`FocusCamera.tsx:20`), ignoring Saturn's ring geometry (3.8× ring outer radius × 1.2 scale × 1.9 visual radius ≈ 8.66 units).

#### 1.5 Wire Draco Decoder into `useGLTF`

**File**: `client/src/lib/draco-setup.ts`

Current code creates a `DRACOLoader` but never connects it to `useGLTF` — it's dead code. The correct approach uses drei's static setter:

```ts
import { DRACOLoader } from 'three/addons/loaders/DRACOLoader.js';
import { useGLTF } from '@react-three/drei';

let initialized = false;

export function initDracoDecoder() {
  if (initialized) return true;
  try {
    const loader = new DRACOLoader();
    loader.setDecoderPath('/draco/');
    useGLTF.setDRACOLoader(loader);
    initialized = true;
    console.log('[Draco] Decoder wired into useGLTF');
    return true;
  } catch (error) {
    console.warn('[Draco] Failed to initialize', error);
    return false;
  }
}
```

## Phase 2a: Preload Removal + Fallback Spheres + invalidate() Fixes

### Overview

Remove the 163 MB synchronous `useGLTF.preload` that blocks module evaluation and first paint. Fallback spheres render immediately as Suspense fallbacks. Add the missing `state.invalidate()` call in `Planet.tsx`'s `useFrame` so planets animate during tour pause. Ensure the first frame always triggers via an initial `invalidate()`.

### Changes Required

#### 2a.1 Remove Module-Level `useGLTF.preload` Loop

**File**: `client/src/components/solar-system/Planet.tsx:16-18`
**Changes**: Delete the for-loop that preloads all GLBs at module evaluation time.

Delete:
```ts
for (const b of BODIES) {
  if (b.glbUrl) useGLTF.preload(b.glbUrl);
}
```

This is a top-level module statement — it runs when the file is first imported by any module (typically during the React component tree initialization). Removing it means GLBs only load when the per-planet `<Suspense>` boundary resolves for each `GLBModel` component individually.

The existing `FallbackSphere` is already the Suspense fallback:
```tsx
<Suspense fallback={<FallbackSphere radius={effectiveRadius} color={body.color} emissive={isSun} />}>
  {body.glbUrl ? <GLBModel ... /> : <FallbackSphere ... />}
</Suspense>
```

Without the preload, each `useGLTF(url)` call inside `GLBModel` triggers a fetch-on-render. The fallback sphere renders instantly; the GLB appears once loaded.

#### 2a.2 Add `invalidate()` to Planet `useFrame`

**File**: `client/src/components/solar-system/Planet.tsx:115-127`
**Changes**: Add `state.invalidate()` at the end of the `useFrame` callback so that `frameloop="demand"` re-renders when planet positions update.

```ts
useFrame((state, delta) => {
  const p = pivot.current;
  if (p) {
    const t = state.clock.elapsedTime;
    const angle = body.phase + t * body.orbitSpeed;
    p.position.x = Math.cos(angle) * effectiveOrbit;
    p.position.z = Math.sin(angle) * effectiveOrbit;
    if (onPosition) onPosition(p.position);
  }
  if (spin.current) {
    spin.current.rotation.y += body.spinSpeed * delta;
  }
  state.invalidate();
});
```

This ensures that even when the tour is paused and `CinematicTour` stops calling `invalidate`, the planets continue to re-render their orbital motion. Without this, planets appear frozen during `OrbitControls` (free-look) mode because nothing triggers a canvas update.

#### 2a.3 Initial `invalidate()` on Canvas Mount

**File**: `client/src/components/solar-system/SolarSystem.tsx:42-47`
**Changes**: Add `onCreated` callback to ensure the first frame renders. With `frameloop="demand"`, the canvas renders one frame on mount automatically, but adding an explicit `invalidate()` in `useFrame` (from step 2a.2) across all 9 planets ensures the first frame is always triggered.

Also add an explicit initial invalidate in `onCreated`:


## Phase 2b: Context-Loss Recovery + Reload UI

### Overview

Add event listeners for `webglcontextlost` and `webglcontextrestored` on the canvas element. Show a recovery overlay when context is lost, auto-invalidate on restore, and provide a manual reload fallback if recovery fails.

### Changes Required

#### 2b.1 Add Context Loss Event Listeners

**File**: `client/src/components/solar-system/SolarSystem.tsx`
**Changes**: Add `onCreated` handler with context loss/restore listeners. Add local state for context loss overlay.

Add import:
```ts
import { useState } from "react"; // already imported
```

Update `onCreated` (merging with the initial invalidate from 2a.3):

```tsx
export default function SolarSystem() {
  const [contextLost, setContextLost] = useState(false);
  // ... existing state ...

  return (
    <div className="relative h-screen w-screen overflow-hidden bg-black">
      <Canvas
        camera={{ position: [0, 12, 38], fov: 55, near: 0.1, far: 1000 }}
        dpr={[1, 1.75]}
        gl={{ powerPreference: "high-performance" }}
        frameloop="demand"
        onCreated={(state) => {
          state.invalidate();
          const canvas = state.gl.domElement;
          canvas.addEventListener('webglcontextlost', (e: Event) => {
            e.preventDefault();
            console.warn('[WebGL] Context lost');
            setContextLost(true);
          });
          canvas.addEventListener('webglcontextrestored', () => {
            console.log('[WebGL] Context restored');
            setContextLost(false);
            state.invalidate();
          });
        }}
      >
```

#### 2b.2 Recovery Overlay UI

Add after the `LoadingSpinner` and `DebugPanel` in the JSX tree (before the closing `</div>`):

```tsx
{contextLost && (
  <div className="pointer-events-auto fixed inset-0 z-50 flex flex-col items-center justify-center bg-black/90 backdrop-blur-sm">
    <div className="mb-4 h-12 w-12 rounded-full border-2 border-amber-500/60 border-t-transparent animate-spin" />
    <p className="text-sm font-medium text-white/80">Graphics rendering lost</p>
    <p className="mt-1 text-xs text-white/40">Recovering...</p>
    <button
      onClick={() => window.location.reload()}
      className="mt-6 rounded-lg border border-white/20 bg-white/5 px-6 py-2 text-xs font-medium text-white/70 transition hover:bg-white/10"
    >
      Reload page
    </button>
  </div>
)}
```

The auto-recovery path: when `webglcontextrestored` fires, `setContextLost(false)` hides the overlay and `state.invalidate()` re-renders the scene. The manual "Reload page" button is a fallback in case the restore event never fires (e.g., GPU driver crash).
